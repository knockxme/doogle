## Part A. Problems in the package (fix before wiring it up)

### A1. Security: files are served with their stored type on the app's own address (must fix)

`methods.ts` `get()` sends `Content-Type: node.mimeType` with no `nosniff`, no sandbox CSP, and no `Content-Disposition`. Files uploaded through the web UI can be `text/html` (and older ones `image/svg+xml`). Opening `https://your-domain/api/dav/x.html` would then run script on the app's address, where the sign-in tokens live in localStorage. Commit `021bba4` closed this hole for normal downloads.

Fix: in `get()`, always send `Content-Type: application/octet-stream`, `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox; default-src 'none'`, the same as `modules/files/content-type.ts` (`setFileSecurityHeaders`). rclone ignores the type. `getcontenttype` in PROPFIND can still report the real type.

### A2. Security: the sign-in failure limit can be bypassed (must fix)

`auth.ts` `clientIp()` with `trustProxy` reads the **first** `X-Forwarded-For` entry. A client can write anything there, because nginx's `$proxy_add_x_forwarded_for` appends to whatever the client sent. An attacker who sends a new fake IP on every request is never limited.

Without `trustProxy`, every request appears to come from the nginx container, so 10 wrong tries from anyone lock out the Pi too.

Fix: count from the right. Take the entry that the trusted proxies added: with `DAV_PROXY_HOPS=1` (app nginx only) use the last entry; with an outer Caddy/Traefik use `DAV_PROXY_HOPS=2`. Or reuse Express `req.ip` with the app's `trust proxy` setting (open audit item 2: make the hop count configurable once for login and WebDAV).

Also:
- WEBDAV.md says `DAV_TRUST_PROXY` defaults to `true`; `config.ts` defaults to `false`. Make them agree.
- `fails.clear()` at 10,000 entries lets an attacker reset every counter by flooding. Drop the oldest entry instead.

### A3. Replace is not atomic (should fix)

`put()` uploads `.dav-upload-<uuid>`, then calls `remove(existing)` and then `move(temp → name)` as separate steps. A crash or error between them leaves the old file deleted and the new one stuck under the hidden temp name. To the client the file is gone, and the web UI shows a `.dav-upload-…` file forever.

`move()` with overwrite has the same gap.

Fix: add one port, for example `replace(user, newId, existingId | null, parentId, name)`. It renames the new file and removes the old File row in **one database transaction**, then deletes the old blobs afterwards (failures go to `OrphanBlob` as today). `put()` and `move()` call it.

### A4. Empty files (decision needed)

The smoke test expects `PUT` of a 0-byte file to return 201. rclone, Sonarr and Jellyfin do create empty files (`.ignore`, placeholder `.nfo`). This repo refuses empty uploads (`UPLOAD_SIZE_REQUIRED`, a spec decision), and `writeEncryptedChunk` cannot handle size 0.

Options:
1. **(Recommended)** Store empty files as a File row with no copies and no blobs. Reads return an empty body. Repair, health and the read path must skip `sizeBytes = 0`. The web UI can keep refusing empty uploads.
2. Refuse with 403 over WebDAV. rclone then logs an error for each empty file and retries it.

### A5. Smaller fixes in the package

- `PIECE_SIZE` must be `UPLOAD_CHUNK_PLAINTEXT` from `modules/crypto/frames.ts` (8,388,384 bytes, not 8 MiB). A wrong value breaks every upload with `CHUNK_NOT_ALIGNED`.
- Code style and place: move it to `backend/src/modules/webdav/` (repo convention) and drop the semicolons. Delete `dev/` from production builds, or keep it only for tests.
- PROPFIND calls `quota()` for every folder listing. In this repo that runs several groupBy queries and may resync Google quotas. Cache the quota per user for 30 seconds.
- `xml.ts` `esc()` does not strip control characters, which are invalid in XML 1.0. A name containing one breaks rclone's parser for the whole folder. Replace them with `�` in output.
- Names containing `/` can be made in the web UI (rename allows any 1 to 255 characters). Over WebDAV they cannot be reached, because `splitPath` rejects an encoded `/`. Either forbid `/` and `\` in web names, or accept that these files are hidden from WebDAV.
- In `nginx-webdav.conf`, `location /api/dav/` makes nginx answer `/api/dav` (no slash) with a 301 redirect. rclone's base URL has no trailing slash and a redirected PROPFIND may fail. Use `location /api/dav` (no trailing slash) or add an exact `location = /api/dav` block with the same settings.

## Part B. How it maps onto this repo

### B1. Mounting (`app.ts`, `server.ts`)

- Mount at **`/api/dav`** in the backend and use the package's nginx block as written (`proxy_pass http://backend:4000;` with no path, so nginx keeps `/api/dav`). Dev (backend on :4000) and Docker then use the same path. `DAV_PUBLIC_PREFIX=/api/dav`, `DAV_STRIP_PREFIX` empty.
- It must come **before `cors()`**, not only before `express.json()`. The `cors` package answers every `OPTIONS` request itself with 204 and never calls the next handler, so WebDAV `OPTIONS` would lose its `DAV` and `Allow` headers.
- `express.json()` would swallow the body of any PUT sent as `Content-Type: application/json` (a `.json` file) and fail at 1 MB. Mounting first avoids it.
- Errors from WebDAV are plain text with WebDAV status codes, not `{ code, message }`. Note this exception in `AGENTS.md`.
- `server.ts`: keep the server returned by `app.listen` and set `requestTimeout = 0` and `headersTimeout = 60_000`. Node 20 cuts every request after 300 s (checked). This also affects the existing `POST /uploads` and `POST /api/v1/uploads` today, so it is worth doing anyway.
- `frontend/vite.config.ts`: `/api/` is already in the service-worker denylist. No change.

### B2. Authentication (`authenticate`)

- API keys today have the single scope `files:upload` (`api-key.routes.ts`). Existing keys must **not** silently gain read and delete rights. Add a scope `dav` (full read, write and delete for that user), and let the user choose it when creating a key on the API Keys page.
- Move the checks in `middleware/api-key.middleware.ts` into one function, for example `verifyApiKey(rawKey, scope)`, and use it in both places. It covers hash lookup, `status`, `revokedAt`, `expiresAt`, user `status`, `mustChangePassword` and `lastUsedAt`. Then also check that the key's user email matches the Basic username, ignoring case.
- The 60-second cache of good keys must be cleared when:
  - an API key is revoked (`api-key.routes.ts` DELETE)
  - a user is disabled (`admin-users.routes.ts` PATCH)
  - a user is deleted (`admin-users.routes.ts` DELETE)

  Export a `forgetDavLogins()` from the webdav module and call it there.

### B3. Tree (`rootFolder`, `child`, `children`, `createFolder`)

- Root: a virtual node `id: 'root'`, mapped to `folderId = null` (files) and `parentId = null` (folders).
- `children`:
  - files with `userId` and `folderId` set and `status: 'active'`
  - folders with `userId` and `parentId` set and `deletedAt: null`

  Every File row in this repo is already a finished upload (the row is created only when both copies are complete), so there is no "unfinished" filter.
- `child`: names are `utf8mb4_unicode_ci` (checked), so a query matches regardless of case and accents. **Do not change the column to `utf8mb4_bin`:** the web search uses Prisma `contains` and would become case-sensitive. Query by name as usual, then keep only exact matches in code (`row.name === name`).
- Duplicates: the web UI allows two files with the same name in one folder, and a file and a folder with the same name. A MySQL unique index cannot prevent it either, because `folderId` and `deletedAt` are NULL (MySQL treats NULLs as different). Rule for `child()`: a folder wins over a file, then the newest file wins. When WebDAV creates a name, it replaces the newest match.
- `createFolder`: move the body of `POST /folders` into a small service and call it from both.

### B4. Upload (`beginUpload`, `writePiece`, `commit`, `abort`)

| Port | Call |
| --- | --- |
| `beginUpload` | `startEncryptedUpload({ userId, plainSize, fileName, mimeType: normalizeMimeType(...), folderId })`. Map `PoolError` (`NO_ACCOUNT_WITH_ENOUGH_SPACE`, `USER_STORAGE_LIMIT_REACHED`) to `DavError(507)`, and `UploadError` 502 to `DavError(503)`. |
| `writePiece(i, buf)` | `writeEncryptedChunk(sessionId, BigInt(i) * BigInt(UPLOAD_CHUNK_PLAINTEXT), buf)`. On `UPLOAD_CHUNK_RETRY`, retry the same call up to 3 times: it is safe because it trims bytes a copy already holds. The last piece returns the created File; keep it. |
| `commit` | The File already exists. Set `contentModifiedAt` from `X-OC-Mtime` (or now) and return the node. |
| `abort` | `failUpload(sessionId, reason)`. It already aborts both copies right away. |

- Size limit: use the existing `MAX_UPLOAD_BYTES` for WebDAV too, instead of a second `DAV_MAX_FILE_GB`. In `docker-compose.yml` it is hard-coded to 5 GB. Change it to `${MAX_UPLOAD_BYTES:-5368709120}` so `.env` can raise it.
- A crash or restart during a PUT leaves the upload session `uploading`: space is reserved for 7 days and S3 parts stay behind. This is open audit item 1. Build the stale-upload cleanup job **before** WebDAV, because rclone retries make abandoned sessions common. The same job should delete leftover `.dav-upload-*` File rows older than one day, if A3 keeps temp names.
- The activity log records `UPLOAD_FILE` with the temp name. Log the final name in `replace` instead.
- A 20 GB file needs two accounts with 20 GB free each (both copies are whole files).

### B5. Read (`readPiece`)

- Load with `readableFileArgs`, where `{ id, userId: user.id, status: 'active' }`. A wrong owner returns `DavError(404)`.
- `openDecryptedStream(file, { start: i*P, end: min(size, (i+1)*P) - 1 })` and collect it into a Buffer. `P` equals 8 frames, which is the read path's batch size, so each piece is one provider range request with copy failover.
- Plaintext pieces live only in RAM (`DAV_CACHE_MB`). This keeps the "no plaintext on disk" rule on the server.

### B6. Delete and move (`remove`, `move`)

- Permanent file delete: the `/files/batch/permanent` steps (`deleteFileCopies` then `file.delete`). Move them into a shared function.
- Folder delete: move the body of `DELETE /folders/:id` into a service and call it from both. That route deletes active files and soft-deletes folders, but **leaves trashed files** of those folders behind. The service should delete those too when permanent.
- There is no folder trash in this repo. With `DAV_PERMANENT_DELETE=false`, files can go to trash, but folders cannot. Simplest: drop the setting and always delete permanently over WebDAV, as the package recommends anyway.
- Blob deletion runs while the request waits. Deleting a big folder over WebDAV can take minutes, and rclone's default timeout is 5 minutes. Acceptable at first. Later: delete the rows, answer, and remove the blobs in the background through `OrphanBlob`.
- `move`: file means `file.update({ name, folderId })`; folder means `folder.update({ name, parentId })` with the descendant check from `PATCH /folders/:id` (move it into the service). Check that the target folder belongs to the user.

### B7. Database (Prisma migration, not raw SQL)

Repo rule: schema changes only through Prisma migrations. The package's SQL becomes:

```prisma
model File {
  // ...
  contentModifiedAt DateTime? @map("content_modified_at") @db.DateTime(3)
  @@index([userId, folderId, name])
}
model Folder {
  // ...
  @@index([userId, parentId, name])
}
```

The migration fills it in: `UPDATE files SET content_modified_at = created_at`. The upload pipeline sets it on every new file. `toNode` uses `contentModifiedAt ?? createdAt`, never `updatedAt` (Prisma bumps that on rename).

No collation change (see B3).

### B8. Quota (`quota`)

`userAvailable(user.id)` from `modules/storage/pool.ts`. `usedBytes` is the user's real size including trash. `availableBytes` is the lower of limit-left and pool-usable, or `null` when both are unlimited. Cache it for 30 seconds (A5).

### B11. Raspberry Pi

- Building on the Pi itself is simplest: Prisma and argon2 then fetch the arm64 binaries natively. For `docker buildx --platform linux/arm64` on another machine, check that `argon2` installs on `node:20-alpine` arm64. If not, add `python3 make g++` to the build stage. Also check that `prisma generate` runs under emulation.
- `rclone mount --vfs-cache-mode full` keeps **decrypted** media on the Pi's SSD. This is outside the server's no-plaintext rule. Fine for a media library, but write it in the README's trust model, and consider an encrypted SSD.
- WebDAV uses Basic auth: the API key travels with every request. Only over HTTPS, or over LAN/Tailscale using the `allow`/`deny` lines.
- Initial import: Google allows about 750 GB a day per account. Importing a 1 TB library will pause accounts for 24 hours. Copy in batches, or use `rclone copy --bwlimit` overnight.

## Decisions (owner, 2026-11-18)

1. Empty files (A4): stored as File rows with no copies and no blobs. Reads return an empty body; Repair, health and the read path skip `sizeBytes = 0`. The web upload keeps refusing empty files.
2. WebDAV deletes are always permanent. `DAV_PERMANENT_DELETE` is dropped.
3. Replace (A3): a `replace` port that swaps the new file in and removes the old row in one transaction; old blobs are deleted afterwards (failures to `OrphanBlob`).
4. WebDAV access is admin-controlled: a per-user switch "WebDAV allowed" in Admin > Users (new `User.davEnabled`, default false). Only users with the switch on can create a key with the `dav` scope on the API Keys page. Turning the switch off revokes that user's `dav` keys and clears the login cache. `authenticate` also requires the switch.
